# 회계관리 (중국법인 월별 재무제표 취합)

중국 법인 산하 지점(사무소)별 담당자가 매월 손익계산서(P&L)/재무상태표(B/S)/현금흐름표(CF)를
입력하고, 본사 회계담당자가 이를 지점별로 조회하거나 법인 단위로 통합해서 볼 수 있도록 만든 웹
도구입니다. 관리부 ERP 통합시스템의 첫 번째 데이터 모듈로, 회계관리 → 예산관리 → 자금집행 →
실적분석으로 이어지는 파이프라인의 출발점입니다. 한국어/中文 2개 언어를 지원합니다.

접대비 앱과 동일하게 바닐라 HTML/JS/CSS + Supabase + GitHub Pages 구조입니다. 다만 Supabase
프로젝트는 접대비와 **별도의 관리부 ERP 전용 프로젝트**를 씁니다 (예산관리/자금집행/실적분석과는 공유).

## v2 업데이트 (실제 재무자료 검토 반영)
YJC 포워딩·상해물류센터가 사용하는 회계프로그램의 실제 PL/BS 리포트를 검토해 다음을 반영했습니다.
- **법인(corp) → 지점(office) → 법인 통합** 구조로 확장. 한 법인 아래 여러 지점(상해/청도 등)이
  각자 입력하고, admin.html에서 "법인 통합 보기"로 지점 합산본을 볼 수 있습니다.
- **실제 계정과목(COA) 70개**로 교체 (기존 21개 플레이스홀더 대체). PL 16개는 실제 회계프로그램의
  6자리 코드를 그대로 쓰고, BS 54개는 원본 리포트에 코드가 없어 라인번호 기반 코드(BS-L##/BS-R##)를
  새로 부여했습니다. CF는 이 회사 회계프로그램이 리포트를 생성하지 않아 플레이스홀더 4개로 수기
  입력했으나, v5에서 표준 서식 실제 라인 35개로 교체되었습니다 (아래 v5 참고).
- **전용 업로드 파서 추가**: YJC 포워딩·상해물류센터는 submit.html의 PL/BS 탭에서 "① 회계프로그램
  다운로드 파일 그대로 업로드" 버튼으로 원본 .xls 파일을 그대로 올리면 자동 반영됩니다. 다른 법인은
  기존 "② 빈 양식 업로드" 방식을 계속 씁니다.
- 원장자료/序时账(287개 초세분화 거래 데이터)는 **파싱 대상이 아닙니다** — 법인마다 회계프로그램이
  달라 이 레벨로 통합하는 건 지속가능하지 않다고 판단해, 감사 참고용 원본 파일로만 별도 보관합니다.

## v5 업데이트
- **제출 잠금(1회 제출)**: PL/PL(한국)/BS/CF 각 탭은 제출 전 경고 문구를 확인한 뒤 제출하면 자동으로
  잠깁니다(`acct_submission_lock`, 법인×지점×적용월×제표종류 단위). 잠긴 탭은 지점 스스로 수정할 수
  없고, 본사가 admin.html의 "법인별 제출 현황"에서 마감 해제(`unlock_submission`)해야 다시 제출할
  수 있습니다. 기존 월 전체를 한 번에 잠그는 "월마감"(`acct_closed_months`)과는 별개 메커니즘입니다.
- **현금흐름표 실제 계정과목**: CF 플레이스홀더 4개를 표준 现金流量表(会企03表) 서식의 실제 라인
  35개로 교체했습니다(코드는 원본 서식의 行次를 반영한 `CF-01`~`CF-82`). 빈 업로드 양식도 이 계정에
  맞게 자동 갱신됩니다.
- **합병 재무제표**: admin.html의 "합병 재무제표" 탭에서 법인을 고르면 그 법인 산하 모든 지점을
  계정별로 합산한 손익계산서/재무상태표/현금흐름표를 표준 서식(스크린샷 제공 리포트)과 같은 구성으로
  볼 수 있습니다 — 손익계산서·현금흐름표는 당월실적/당해 1~당월 누계, 재무상태표는 당월말/전기말
  잔액을 나란히 비교합니다. 엑셀 다운로드도 지원합니다.
- **제출 현황 필터 버그 수정**: admin.html "법인별 제출 현황"에서 특정 지점을 클릭해도 같은 법인의
  다른 지점 데이터까지 함께 보이던 문제를 고쳤습니다 — 이제 법인×지점 단위로 정확히 필터링됩니다.
- **적용년월 전환**: submit.html에서 적용년월을 바꿀 때 더 이상 index.html로 돌아가 재로그인할
  필요가 없습니다 — 상단 컨텍스트바에서 바로 다른 달로 전환할 수 있습니다.

## v4 업데이트
- **법인별 지점 제한**: 법인을 고르면 그 법인이 실제 쓰는 지점만 선택할 수 있습니다 (`config.js`의
  `CORP_OFFICES`). 예: 상해물류센터는 CY/창고/운송만, 청도CY는 청도만.
- **원본파일 그대로 업로드 기능 제거**: PL/PL(한국)/BS 전부 "빈 양식 다운로드 후 업로드" 또는
  수기입력만 지원합니다.
- **PL(한국)에 출장비 추가**: 인원수·접대비 옆에 출장비 월간 합계도 함께 입력합니다
  (`acct_pl_kr_extra.travel_cny`). 실적분석은 이제 이 값을 씁니다 (예산관리 일반관리비 실적 대신).

## v3 업데이트 (한국회계기준 손익계산서 추가)
본사에 보고하는 "한국회계기준 영업이익"은 일반 PL(중국 분류)의 영업이익(799999)과 계산 범위가
다릅니다(기타영업수익/비용을 어디까지 포함하는지가 다름). 이를 위해 **PL(한국)**이라는 별도
statement_type을 새로 추가했습니다.
- submit.html에 "손익계산서(한국)" 탭 추가. 회사 회계프로그램에서 다운로드하는 전용 리포트
  파일(예: `YYYYMM YJCSHA PL (한국).xls`)을 그대로 업로드하면 자동 반영됩니다 (기존 PL 파서를
  그대로 재사용 — AC CODE 기반이라 컬럼 구성이 달라도 인식).
- 이 탭에서 **인원수**와 **접대비 월간 합계**(접대비 앱은 별도 Supabase 프로젝트라 자동 연동이
  안 되어 수기 입력)도 함께 입력합니다. 실적분석의 목표실적 관리표에서 이 데이터를 사용합니다.
- PL과 PL_KR은 같은 AC CODE(500000 등)를 공유하므로 `acct_accounts`의 기본키를
  `(code, statement_type)` 복합키로 변경했습니다.

## 접대비와의 차이점
- **계정과목 기반 입력**: 자유 입력 행이 아니라 표준 계정과목(COA)이 입력 행을 정의합니다.
- **접근키 기반 권한 제어**: 접대비는 전직원 오픈이었지만, 회계관리는 지점별/역할별로 데이터를
  분리해서 봐야 하므로 접근키(access key) 체계를 도입했습니다. 이 체계는 향후 예산관리·자금집행·
  실적분석·인사관리가 그대로 재사용할 공용 컴포넌트입니다. `office_scope`로 지점 단위까지 좁힐 수
  있습니다.
- **월별 고정환율**: 접대비처럼 항목마다 직접 CNY→KRW를 입력하는 대신, 관리자가 월 1회 환율을
  설정하면 전체 데이터에 일괄 적용됩니다.

## 구성
- `docs/` — GitHub Pages로 배포되는 프론트엔드
  - `index.html` — 법인/지점/적용년도월/담당자/접근키 입력
  - `submit.html` — 지점 담당자가 P&L/B/S/CF 3개 탭으로 재무제표 입력, 자동저장, 회계프로그램
    파일 그대로 업로드(YJC/상해물류센터) 또는 빈 양식 업로드(그 외 법인)
  - `admin.html` — [본사용] 접근키로 로그인 후 지점별 집계 조회 또는 법인 통합 조회, 제출현황,
    환율설정, 월마감, 계정과목 관리, 엑셀 다운로드
- `supabase/` — 테이블/함수 정의 (`schema.sql`), 실제 계정과목(`seed_accounts.sql`), 테스트
  접근키(`seed_access_keys.sql`)

## 배포 방법
`supabase/README-deploy.md`를 따라 Supabase에 스키마를 적용한 뒤,
`docs/js/config.js`의 `SUPABASE_URL`/`SUPABASE_ANON_KEY`를 채우고 GitHub Pages로 배포하세요.

## 로컬 실행
```
python -m http.server 8090 --directory docs
```

## 접근키
평문 키는 서버에 저장되지 않고 해시만 저장됩니다. 발급/교체 방법은 `supabase/README-deploy.md`
"접근키 발급/교체" 섹션을 참고하세요. 테스트용 키는 `supabase/seed_access_keys.sql`에 있습니다
(실제 운영 전 반드시 교체).

## 커스터마이징
- 법인/지점 목록: `docs/js/config.js`의 `CORPORATIONS`/`OFFICES`
- 다국어 문구: `docs/js/i18n.js`
- 계정과목: 코드 수정 없이 admin.html에서 엑셀 업로드로 교체 (`supabase/seed_accounts.sql`은 초기값)

## ⚠ 이 모듈의 계정코드를 바꾸면 다른 모듈도 함께 갱신해야 합니다
예산관리는 PL 계정과목을 그대로 참조하고, 자금집행(`get_dividend_available`)과 실적분석
(수익성/안정성 지표 계산)은 특정 계정코드를 하드코딩으로 참조합니다. 계정과목을 다시 교체하면
각 모듈의 `supabase/README-deploy.md`를 참고해 해당 RPC들도 새 코드에 맞게 갱신하세요.
